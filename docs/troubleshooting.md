# Лечилка VOICEog: симптом → причина → лечение

Живая шпаргалка на все грабли, которые мы уже прошли: окно, трей, микрофон,
пакеты, горячие клавиши. Ищешь по симптому в левой колонке — читаешь, чем
лечить. Если что-то из этого вернулось, значит либо сборка старая, либо файл
подменили.

> Правило номер один: **сначала запусти из терминала**. Половина «не работает»
> рассыпается на живых строчках в консоли. Куда смотреть — в конце файла.

## Мини-разделы

### Почему у нас запись через AudioWorklet, а не MediaRecorder
`MediaRecorder` в WebKitGTK кодирует звук через GStreamer и отдаёт **пустой
блоб** — ноль байт, а снаружи всё гладко. Мы перестали доверять браузерному
кодировщику: `getUserMedia` → **AudioWorklet** (`public/pcm-worklet.js`) →
сырой **PCM s16le** → страница навешивает 44-байтный WAV-заголовок →
`POST /transcribe`. Если снова «тишина» — смотри worklet и свежесть морды.

### Почему `WEBKIT_DISABLE_DMABUF_RENDERER=1` — не костыль
Это стандартный обходной путь для WebKitGTK под Wayland. DMABUF-рендерер
быстрый, но на связке с некоторыми драйверами валит окно на старте
(`Gdk-Message: Error 71 … dispatching to Wayland`). Платим чуть меньшей
плавностью — не работоспособностью. В бинарь переменная зашита первой строкой
(до инициализации GTK), в AppImage — в AppRun-хуке. Позже уже поздно: если
запускаешь сам — выставь заранее.

### Про single-instance
Так и задумано (by design). Защита живёт в бинаре: первый экземпляр занимает
имя в D-Bus (`zbus`), второй не плодит окно, а будит первое и выходит.
`run-window.sh` поверх этого ещё и сам не запускает второй пульт
(`pgrep -x voiceog-window`). `VOICEOG_WINDOW_ALLOW_MULTI=1` (он же
`ALLOW_MULTI=1`) снимает **только** `pgrep`-проверку лончера — zbus-защита в
бинаре независима. Реально два окна возможны лишь там, где нет сессионного
D-Bus.

## Где смотреть логи

```bash
# 1. Запуск из терминала — лучший способ увидеть правду (GTK/WebKit + шаги скрипта)
~/Projects/VOICEog/scripts/run-window.sh

# 2. Лог сервера (если поднят вручную/через автозапуск с логом)
cat server.log
# run-window.sh exec-ит `node src/server.mjs` и пишет прямо в консоль

# 3. Жив ли сервер
# 7777 — дефолт; при своём порте подставь $VOICEOG_PORT (пример ниже)
curl -s "http://127.0.0.1:${VOICEOG_PORT:-7777}/health"   # {"ok":true,"model":"..."}
pgrep -x voiceog-window                        # номер процесса окна
ss -tlnp | grep "${VOICEOG_PORT:-7777}"        # слушает ли кто порт

# 4. systemd-вариант автозапуска сервера
systemctl --user status voiceog
systemctl --user show-environment | grep -E 'WAYLAND_DISPLAY|DISPLAY'

# 5. Что вообще есть в системе
./voiceog doctor
```
