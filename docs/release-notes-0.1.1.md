# VOICEog 0.1.1

**Дата:** 2026-09-27 · **Тип:** patch (мелкое исправление, без новых функций)

Окно на NVIDIA + Wayland больше не лагает. Возвращаем аппаратный рендер (GPU) —
раньше ради стабильности его глушили, и всё рисовалось на процессоре.

---

## Главное: окно снова летает на NVIDIA + Wayland

- **Было:** чтобы окно вообще запускалось на NVIDIA + Wayland, мы выключали
  GPU-рендер (`WEBKIT_DISABLE_DMABUF_RENDERER=1`). Окно жило, но отрисовку тащил
  CPU — отсюда лаги.
- **Стало:** GPU-рендер включён. На NVIDIA + Wayland окно само ставит
  `WEBKIT_DISABLE_DMABUF_RENDERER=0` + `__NV_DISABLE_EXPLICIT_SYNC=1`. Работает из
  коробки, ничего настраивать не надо.
- **Проверить, что GPU правда работает.** Самый надёжный признак — WebKit-процесс
  держит открытым узел рендера:

  ```bash
  PID=$(pgrep -f WebKitWebProcess | head -1)
  ls -l /proc/$PID/fd | grep dri
  ```

  Если в выводе есть `/dev/dri/renderD128` — рендер идёт через GPU: процесс занял
  узел и держит его открытым. Пусто — сидит на CPU.

  Дополнительно можно глянуть по видеопамяти:

  ```bash
  nvidia-smi | grep -i WebKit
  ```

  Если тут видно `WebKitWebProcess` с занятой VRAM — тоже подтверждение. Но одного
  `nvidia-smi` мало: GBM-клиент может работать через GPU и не светиться в этом
  списке, поэтому основной признак — открытый `/dev/dri/renderD128`
  (так же, как в `docs/window.md`).
- **Если снова глючит** (белое окно, падение) — аварийная ручка в старый CPU-режим:

  ```bash
  VOICEOG_DISABLE_DMABUF=1 ./scripts/run-window.sh
  ```

  Это фолбэк, а не основной путь.

## Почему это было сломано

- `Error 71` (`Gdk-Message: ... dispatching to Wayland`) — известный баг связки
  **NVIDIA (проприетарный драйвер) + Wayland + GTK/WebKitGTK**.
- В апстриме он **до сих пор не починен** — поэтому костыль на нашей стороне.
- Корень — **explicit sync**: протокол синхронизации кадров, который
  проприетарный NVIDIA и Wayland вместе не тянут.
- Обход: explicit sync гасим (`__NV_DISABLE_EXPLICIT_SYNC=1`), а сам GPU оставляем
  включённым. Раньше гасили весь GPU — это и было ошибкой.
- Разбор до деталей: `docs/troubleshooting.md` (раздел «Рендер окна: GPU на
  NVIDIA+Wayland и CPU-фолбэк») и `docs/window.md`.

---

## Прочее

- **Ничего не ломали.** Для AMD, Intel, nouveau и X11 (любой Linux) мы не
  добавляем NVIDIA-специфичных флагов — WebKit остаётся на своих дефолтах, мы
  туда не лезем.
- Лончеры и systemd-сервис больше никому **не навязывают**
  `WEBKIT_DISABLE_DMABUF_RENDERER=1` — а раньше навязывали всем. Теперь решение
  принимает сам бинарь.
- Коммиты: `f5601e9` (GPU-рендер в бинаре), `a8aee4d` (лончеры/сервис), `b7a541f` (доки).
