# VOICEog 0.1.0

**Локальный голосовой ввод.** Жмёшь кнопку или хоткей — говоришь — текст падает
куда надо. Без облака, без аккаунтов. Речь распознаётся на твоей машине.

Это первый релиз, и главное в нём — **нативное окно-пульт**. Раньше морда жила во
вкладке браузера: её можно случайно закрыть, она теряется среди других вкладок, нет
иконки в трее. Теперь это отдельная программа `voiceog-window`. Саму морду не
переписывали — в окне тот же веб-интерфейс, просто в своей рамке.

---

## Что нового

- **Окно-пульт** — `voiceog-window` на Rust (tao + wry + tray-icon), ~5.5 МБ.
  Браузерный движок берётся из системы (webkit2gtk), свой Chromium не тащим.
- **Иконка в трее** — через `libappindicator`.
- **Одно окно** — второй запуск не плодит новое окно, а будит уже открытое
  (single-instance через D-Bus/zbus).
- **Микрофон в вебвью** — окно само выдаёт разрешение на микрофон (и только на
  него), навигация разрешена только на адрес морды (по умолчанию
  `127.0.0.1:7777`, меняется `VOICEOG_PORT`/`VOICEOG_URL`).
- **Запись через AudioWorklet** — звук берётся сырым PCM s16le, страница клеит
  WAV. Старый `MediaRecorder` в WebKitGTK отдавал пустой блоб, из-за чего писалась
  тишина; от него ушли.
- **Автозапуск** — при входе в систему окно поднимается само
  (`~/.config/autostart/voiceog-window.desktop`).
- **Лончер** — `scripts/run-window.sh`: поднимет сервер, если надо, откроет окно, а
  при закрытии погасит только свой сервер (чужой не трогает).

## Как поставить

Готовые файлы приезжают из CI по тегу `v*`.

**Linux**

- `.deb` (Debian/Ubuntu/Mint): `sudo apt install ./voiceog-window_0.1.0-1_amd64.deb`
- `.rpm` (Fedora/RHEL/openSUSE): `sudo dnf install ./voiceog-window-0.1.0-1.x86_64.rpm`
- AppImage (любой Linux): `voiceog-window-0.1.0-x86_64.AppImage` (glibc 2.35,
  заводится на Debian 12 / Ubuntu 22.04+):
  `chmod +x voiceog-window-0.1.0-x86_64.AppImage && ./voiceog-window-0.1.0-x86_64.AppImage`.
  Такой файл отдаёт CI: он зовёт `window/packaging/appimage/build.sh` на
  `ubuntu-22.04`. Локальная glibc-совместимая сборка
  (`window/packaging/appimage/build-bookworm.sh`) кладёт тот же образ, но с
  суффиксом — `voiceog-window-0.1.0-x86_64-bookworm.AppImage`. Суффикс говорит
  только о том, что образ собран в контейнере `debian:bookworm`; `glibc`-потолок
  у обоих `2.35`, поэтому имена взаимозаменяемы — бери любое.
  Хочешь свой вариант под свежий дистр — это `build.sh` на текущей системе, но
  там потолок `glibc` выше, и для раздачи на старые дистры он не годится.
- Портативный бандл: распаковал `VOICEog-0.1.0-linux-x86_64.tar.zst` → запустил `./run.sh` (окно + сервер в комплекте). Архив ~12 МБ, распакованный ~40 МБ.

**Windows**

- `VOICEog-setup.exe` — ставится per-user, без прав админа, в `%LOCALAPPDATA%\VOICEog`.
  Собирается только CI на Windows (кросс-сборкой не делается).

**Что нужно на машине**

- Linux для окна: `webkit2gtk-4.1`, `gtk3`, `libayatana-appindicator3` (иначе окно/трей не заведутся).
- Node.js 20+ — для портативного бандла (в `.deb`/`.rpm`/AppImage сервер **не входит**, он ставится отдельно из исходников).
- Модель распознавания не летит в архив — качается при первом запуске
  (архив ~487 МБ, распаковывается в ~641 МБ на диске).
- Для диктовки по хоткею — микрофон, буфер (`wl-copy`/`xclip`), Ctrl+V (`ydotool`/`wtype`), доступ к `/dev/input`.

## Известные ограничения

- **glibc.** Собранное на свежем дистре не заведётся на старом. Релизные пакеты
  собирает CI на `ubuntu-22.04` (glibc 2.35); локальная сборка — только для проверки.
- **AppImage и системные deps.** Трей в образе работает, но при сборке нужен
  dev-пакет `libayatana-appindicator3-dev` — иначе скрипт падает, а не собирает
  образ без трея.
- **Windows-нативники собираются только на Windows.** `node_modules` под win
  (sherpa-onnx, uiohook-napi, ffmpeg-static) кросс-сборкой не лечатся — идут из CI
  или с Windows-машины.
- **`.exe` невоспроизводим.** Даже при заданном `SOURCE_DATE_EPOCH` PE
  `TimeDateStamp` и случайный PDB GUID при линковке «гуляют» — MSVC-линкер тут
  недетерминирован. Пакеты Linux при этом берутся байт-в-байт. Сборка `.exe`:
  локально `cargo xwin`, в CI — MSVC.
- **`window/` должна быть в репе.** Проверь перед релизом: `git ls-files window`
  не пусто. Если её нет в чекауте, job `windows` честно падает (не находит
  `window/packaging/windows/sidecar/provision.sh`), а `release` (needs:
  `[linux, windows]`) не стартует — то есть релиза нет совсем, а не «без
  `setup.exe`».
- **Трей после перелогина.** Под GNOME нужен `gnome-shell-extension-appindicator` и
  повторный вход — до этого иконки в трее не будет, но программа работает.
- **Только linux-x64 / linux-arm64.** На musl (Alpine) и riscv — сборка из исходников.
